## Implementation notes

- Public seams: `DataSupply.materialize(SourcePartitionRequest)`, `GET /api/v1/research/listings/{listing_id}/price-eligibility`, `GET /api/v1/operations/sources`, the listing eligibility UI, and the `ticket-06-acceptance` Compose profile.
- The source boundary is the shared `SourceCollector`／`SourceDecoder` adapter. Authorization checks all six required source uses before the adapter can be contacted; canonical objects, authorization audit, eligibility, dataset, and adjustment evidence publish transactionally.
- Durable source checkpoints advance only with atomic evidence publication. A provider rate-limit response yields a retryable `deferred` record with `retry_after_seconds` and never advances the checkpoint. Raw content identity is separate from append-only retrieval receipts.
- Historical publication accepts platform-observed or archive-attested evidence for historical training／backtest research, but only through a content-addressed `HistoricalAvailabilityClaim` minted by `TaiwanPriceQualificationWorkflow`; the workflow requires the dedicated `price_qualification.govern` action, current source policy／entitlement, all six required uses, and an atomic authorization audit. Caller-supplied claim mappings and current-only publication claims fail closed.
- Formal research qualification additionally requires the versioned manifest's exact current／historical source lineage plus verified governance artifacts for the historical claim, `DEP-MKT-TW-01` approval provenance, and formal gate. Artifact kind, content hash, approval／contract IDs, policy／entitlement versions, evidence status, source IDs, manifest ID, dependency ID, and permitted use must all match. Synthetic provider-contract rows therefore remain non-formal.
- Every listing and operations eligibility read resolves the currently effective policy／entitlement and six required uses for every non-blocked source. Immutable materialization authorization supplies only the prior subject and the exact dataset／evaluation／decision／trace／correlation binding; its historical environment／protection class are lineage fields and it is never rehydrated as a current authenticated `SecurityContext`. Runtime environment comes from the freshly authenticated metadata request. A different source-workload principal additionally requires a configured current-attributes provider returning an evidence ID, environment, protection classes, and validity interval; missing, mismatched, expired, or future-dated evidence fails closed. The request principal is authorized only for the eligibility-metadata read. Every current-rights result, including missing／invalid evidence and unavailable policy／attribute resolution, is a separate content-addressed `current_source_rights_resolution` artifact linked to the query trace. Revoke, suspend, replacement, or use removal overlays `policy_blocked` on published／quarantined projections before the historical decision's `valid_until`, without rewriting that evidence. A rate-limited source row remains historically `deferred`, while the listing aggregate fails closed as `policy_blocked`; UI reports both the later rights denial and the earlier checkpoint-preserving rate limit.
- Qualification governance writes all evaluated authorization decisions atomically with either the successful claim／gate or a content-addressed rejection record, including mixed allow／deny attempts. Rejection evidence contains only the operation and stable reason code, not the rejected claim payload.
- The manifest now binds ten real XTAI ordinary-share listings to versioned first-party selection evidence, source-content SHA-256 digests, content-addressed retrieval receipts, explicit listing subjects／assertion kinds／effective dates, independent issuer／security／listing IDs, time-bounded aliases, and a `2448` → `3714` predecessor／successor relationship. It covers a cash dividend, separate trading-halt and resume receipts, historical delisting, name history, and the official pre-2001 Saturday shortened-session regime. Evidence swapping, relationship／calendar mismatch, receipt corruption, and name-change-as-ticker-change fail closed at the manifest seam. That calendar case is explicitly not applicable to the modern seven-year training window; no modern Taiwan half day is invented. The source-selection research record is `docs/research/taiwan-10-listing-selection-evidence.md`. The manifest remains `qualification_candidate` because selection evidence is not market-data usage authorization.
- The first criterion remains unchecked. The official research found no same-listing external security-code／ticker value change: `2887` is a display-name change under code `2887`, while `2448` → `3714` is a predecessor／successor relationship between different listing IDs. To complete it, either add a TWSE／issuer record that proves one listing ID changed from code A to code B, with both validity intervals and immutable retrieval receipts, or obtain an explicit spec decision changing the required case to name history plus a cross-listing code transition. The implementation can represent different time-bounded codes on one listing but does not fabricate such evidence.
- The fourth criterion remains unchecked. To unblock it, the source steward／legal／procurement owners must supply the signed `DEP-MKT-TW-01` contract and approval, a current entitlement test and policy version proving all six required uses, and the contracted unadjusted EOD／company-action／symbol-history backfill with at least seven-year retention and sufficient depth for the latest eight quarterly folds. The governed workflow must then mint the qualified historical claim and formal gate from those originals; the existing operations and research seams will expose the resulting contract／approval／policy／entitlement／claim／dataset／adjustment IDs. Synthetic fixtures, public-web research, or a test credential cannot satisfy this criterion.
- Docker／PostgreSQL correction: Windows Docker Desktop is installed even though `docker` is not on `PATH`. Following `docs/agents/docker-acceptance.md`, the resolved CLI under `%LOCALAPPDATA%` passed Compose model validation, PostgreSQL 17 health／migration／role checks, `pytest -m postgresql -q` (1 passed, 174 deselected), and the deployed `ticket-06-acceptance` profile (all six checks true; formal qualification correctly false while the external gate is absent). `docs/development/postgresql-test-environment.md` now points to that required resolution procedure so PATH absence is not reported as Docker absence again.
