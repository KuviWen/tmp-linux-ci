# 06 — 台股合格行情到研究資格狀態

**Zero-cost boundary:** 遵循主 spec `COST-0-01` 與 ADR 0018；允許用途資格合格的零付費 authenticated provider 及程式管理的來源憑證，禁止付費／採購／sales approval／協商契約；憑證未就緒是可觀察狀態，不是 ticket 交付 blocker。

**What to build:** 將 data.gov.tw 逐一明示 OGDL 1.0 的 TWSE 當期 distributions、平台自首次取得日起的不可變 observed-history reader，以及 FinMind 免費 token API 正式候選接入相同 DataSupply 與 Ticket 07 來源憑證契約，從未調整 EOD、公司行動與掛牌／名稱歷史建立可追溯台股資料集、內部調整版本及研究／營運資格狀態。FinMind 能進入正式資格流程但不因註冊、token 或技術 probe 成功而自動合格；使用依據、實得歷史或 reference evidence 不足時完整路徑必須 fail closed。Yahoo／`yfinance` 與獨立 `experimental_reference_only`／`experimental_forecast` 路徑均不採納。

**Blocked by:** 05 — 發布 P1 雙市場工程脊柱 acceptance bundle

**Public source basis:** `TWSE-OGDL-OPEN-DATA-01` 與 `FINMIND-FREE-TAIWAN-MARKET-DATA-01`（後者是正式資格候選，不是已合格依據或 external gate）

**Trace IDs:** `P2-ENTRY-01`, `P2-ENTRY-02`, `P2-TRACE-TW-01`

Status: ready-for-agent

- [x] 原始未調整價格、公司行動及掛牌生命週期建立不可變資料集與內部 AdjustmentVersion，供應商 adjusted close 只能交叉驗證。

## Implementation notes

- Public seams: `DataSupply.materialize(SourcePartitionRequest)`, `GET /api/v1/research/listings/{listing_id}/price-eligibility`, `GET /api/v1/operations/sources`, the listing eligibility UI, and the `ticket-06-acceptance` Compose profile.
- The source boundary is the shared `SourceCollector`／`SourceDecoder` adapter. Authorization checks `ingest`, `retain_observed_history`, `transform`, `model`, `internal_display` and `backup_restore` plus the exact dataset／distribution pair before the adapter can be contacted; `retain_7_years` is not a P2 gate, and actual depth is evaluated from immutable history evidence. Retrieval receipts bind the dataset／distribution pair and observed URI. Canonical objects, authorization audit, eligibility, dataset, and adjustment evidence publish transactionally.
- Durable source checkpoints advance only with atomic evidence publication. A provider rate-limit response yields a retryable `deferred` record with `retry_after_seconds` and never advances the checkpoint. Raw content identity is separate from append-only retrieval receipts.
- Historical publication accepts platform-observed or archive-attested evidence only when a content-addressed `HistoricalAvailabilityClaim` is backed by a distinct platform-minted historical qualification artifact. Candidate claims remain quarantined; caller booleans and public-terms bytes cannot qualify sessions, coverage, actions or listing lifecycle. The workflow requires the dedicated `price_qualification.govern` action, current source policy, all six required uses, and an atomic authorization audit.
- `TaiwanPriceQualificationWorkflow` derives license／terms／attribution and the exact distribution allowlist from the currently authorized policy, verifies captured terms bytes against its pinned hash, stores them in the application `FilesystemObjectRepository`, and publishes only an immutable source-basis artifact. `register_zero_fee_source_basis_evidence` additionally binds FinMind's exact provider、plan、principal classification、credential kind and required five-member bundle, so the candidate can use the same formal gate without inheriting the TWSE OGDL identity. Formal research qualification separately requires verified historical evidence, the manifest's exact current／historical lineage and selection-source archives, and a gate that binds both artifact IDs. Missing, unreadable, incomplete, corrupted or insufficient terms／history archives fail closed; a token、live probe、public-terms artifact、contract ID、procurement approval or external entitlement cannot substitute.
- Every listing and operations eligibility read resolves the currently effective source policy and six required uses for every non-blocked source. Immutable materialization authorization supplies only the prior subject and exact dataset／evaluation／decision／trace／correlation binding. Each current-rights result, including missing／invalid public terms and unavailable policy／attribute resolution, is a separate content-addressed artifact linked to the query trace. Public-terms withdrawal, replacement, or use removal overlays `policy_blocked` without rewriting prior evidence.
- Qualification governance writes all evaluated authorization decisions atomically with either the successful claim／gate or a content-addressed rejection record, including mixed allow／deny attempts. Rejection evidence contains only the operation and stable reason code, not the rejected claim payload.
- The manifest binds ten real XTAI ordinary-share listings to versioned first-party selection research. The accepted edge cases are `2887` display-name history under code `2887` and `2448` → `3714` as predecessor／successor listings with distinct permanent identities. It also covers cash dividend, halt／resume, historical delisting and the official pre-2001 Saturday shortened-session regime; that regime is explicitly outside the modern training window, so no modern XTAI half day is invented. The spec decision now accepts this evidence shape and criterion 1 is complete.
- FinMind is a formal qualification candidate, not an experimental fallback and not a qualified source. Its versioned authenticated source path has separate current／historical adapters, the exact five-member required bundle, and a supplemental current listing reference while reusing Ticket 07's provider registry, distinct adapter identity, write-only credential lifecycle, audit model and `SecretProvider`. The candidate reference graph intentionally leaves lifecycle and company-action completeness false until immutable evidence establishes them; token validation establishes authentication only. Formal history can advance only from a live-provider DataSupply assessment that binds an explicit archive identity／version／revision-as-of, the acquisition-time credential version and lease-pin audit, a passed source-contract assessment, the retrieval receipt, and reopened raw-object hashes. Engineering adapters and ordinary current pulls cannot mint this assessment, and current credential readiness remains part of the public `formally_qualified` result even after a historical gate exists.
- Yahoo／`yfinance` is excluded because the wrapper license does not grant the underlying data rights. No `experimental_reference_only` or `experimental_forecast` namespace, storage, route, UI or publication path is introduced; an unqualified FinMind result remains on the single formal path as `credential_required`、`unavailable` or `policy_blocked`.
- `GET /api/v1/research/listings/{listing_id}/price-eligibility`, `GET /api/v1/operations/sources` and UI now expose `TWSE-OGDL-OPEN-DATA-01`, the exact data.gov.tw dataset IDs, dataset pages, direct distribution URLs and qualification scopes, OGDL license／terms／attribution, all no-account／no-application／no-fee flags, policy／coverage／schema／integrity／actual-depth checks, actual source IDs, and stable `source_basis_unverified`／`qualification_evidence_unverified` states. The current manifest marks the terms as `documented_not_archived`, honestly uses `twse-open-data-observed-history`, remains a `qualification_candidate`, and does not claim seven years. This traceable success／insufficiency boundary completes criterion 4 without external evidence.
- Docker／PostgreSQL correction: Windows Docker Desktop is installed even though `docker` may not be on `PATH`. Following `docs/agents/docker-acceptance.md`, acceptance resolves the CLI under `%LOCALAPPDATA%`; the profile expects formal qualification false while the documented terms／raw archives and observed-history depth are not yet formally verified, and treats that state as transparent local insufficiency rather than a procurement blocker.
- Final local verification: full pytest against the existing PostgreSQL test service (354 passed); `.venv\Scripts\python.exe -m mypy src tests`; `.venv\Scripts\python.exe -m ruff check .`; `.venv\Scripts\python.exe -m ruff format --check .`; `pip wheel --no-deps --no-build-isolation` (`sha256:e1879b0d203a3c7379b7cbaa0683699da204b91e3135082a160adf4b50afdbcf`); and a clean rebuilt `ticket-06-finmind-acceptance` Compose project (11 administrator／REST／UI checks plus 4 isolated source-probe checks all true, `status=passed`). The deployed source probe proves FinMind current／historical `credential_required` without provider contact under an adapter-only identity, while the separate administrator client proves REST／Traditional Chinese UI, write-only set／expired validation／rotation／revocation, false qualification after every unready credential state, and no plaintext token in public responses. The administrator client has neither the source-adapter key nor the source-secret volume; non-init key and object mounts are read-only. Formal qualification correctly remains false because FinMind terms／source rights／immutable history and the TWSE documented terms／raw archives／observed-history depth remain unverified or insufficient.
