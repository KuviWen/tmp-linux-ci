# 07 — 美股零付費認證行情到研究資格狀態

**Zero-cost boundary:** 遵循主 spec `COST-0-01` 與 ADR 0018；允許用途資格合格的零付費 authenticated provider 及程式管理的來源憑證，禁止付費／採購／sales approval／協商契約；憑證未就緒是可觀察狀態，不是 ticket 交付 blocker。

**What to build:** 將至少一個技術上涵蓋 EOD、公司行動及美股 reference／symbol lifecycle 的零付費 authenticated provider（Alpaca、Tiingo 或同等來源）接入共同 DataSupply，並在 Operations 程式頁面完成來源憑證的 write-only 管理與 provider-owned 重新申請路徑。缺少真實用途資格或有效憑證時，同一垂直路徑發布可驗證的 `credential_required`／`policy_blocked`，但 adapter、REST、UI、workflow 及 acceptance 可完整交付。

**Blocked by:** 05 — 發布 P1 雙市場工程脊柱 acceptance bundle

**Source basis:** 待選零付費方案逐 dataset／distribution 建立來源使用依據；真實 live qualification 取決於部署主體符合方案條款及有效憑證，但不存在付費、採購或 sales gate

**Trace IDs:** `P2-ENTRY-01`, `P2-ENTRY-02`, `P2-TRACE-US-01`, `P2-TRACE-CREDENTIAL-01`

Status: ready-for-agent

- [x] 選定的零付費 authenticated adapter 及其 missing-credential path 通過與台灣相同的 Collector／Decoder、checkpoint、rate、policy、coverage、revision、identity 及 reference-graph interface contracts；provider test double／fixture 只證明工程契約，不冒充正式資料。

## Implementation notes

- 公共 seam：共同 `DataSupply.materialize`、研究資格 REST／UI、Operations credential REST／UI，以及隔離的 Ticket 07 Compose acceptance；來源秘密只由可替換 `SecretProvider` 解密並以短生命週期 lease 提供給 validator／collector。
- Alpaca Basic 工程契約涵蓋 raw SIP daily bars、官方 grouped corporate-actions schema、完整分頁、calendar、checkpoint、rate／coverage／revision、永久 listing identity 與內部 AdjustmentVersion；bars、actions 與 calendar 各有獨立 policy、raw object、coverage、schema、gap 與 lineage receipt，member coverage／schema／重複項、correction 及 reference-graph 缺件都會先隔離，provider double 明確只屬 engineering contract。Provider、policy source ID、distribution ID、endpoint、validation contract ID 與各 contract 的必要 assessment evidence 由單一 Alpaca provider contract catalog 定義，authorization、application/runtime wiring、credential validation、live probe、collector／decoder、acceptance、assessment validation 與 source manifest contract test 共用同一 identity，避免任一層靜默漂移。Credential probe 的 passed evidence 必須含單一 bars ticker／dataset；完整 live contract 必須含 10 ticker、三個 dataset、至少兩頁 pagination、通過的 symbol lifecycle probe，以及與當前版本化 universe 完全一致的 manifest ID、reference-graph version 與 permanent listing IDs。Live probe 的 current symbols、歷史下市、ticker change、company-action 及半日市案例皆由同一 manifest／reference graph 推導，不維護第二份 ticker 清單。Assessment listing IDs 在 provider boundary 強制符合 canonical RFC 4122 UUID 表示，OpenAPI 同步發布三項 universe evidence 並將 eligibility／operations descriptions 明列為台美共同 seam。
- Candidate source basis 對每個必要 dataset 明列尚未確認的 allowed uses、歸因、保留／刪除與有效期；Nasdaq current directory 僅是 supplemental reference，不冒充 provider bundle 成員或正式 symbol history。
- Operations 的 set／rotate／revoke／validate 在授權後執行，支援撤銷後重新申請／設定、expiry、stale-validation fencing、補償式 secret write 與持久 cleanup retry；REST 與 US adapter 共用同一個加密 `SecretProvider`，但人員管理 identity 與只具 `market_data.collect` 的 source-adapter workload identity 分離，Compose 亦使用不同的最小權限 key 與 policy。每次 validation checkout 前會重新載入並評估 adapter 的 grant、逐 dataset policy／entitlement、identity expiry、protection class、distribution 及 access mode；identity／policy 缺失或過期時會留下 deny decision，且不接觸 SecretProvider 或 provider。沒有 adapter key 的舊 profile 使用明確 disabled path，不再鑄造具收集權限的 synthetic identity。secret write 在接觸 provider 前先保存 allow 與 `attempted` audit，並保存固定去識別化的 `succeeded`／`failed` 終態；成功終態 audit 失敗時會撤銷剛建立的 secret，撤銷失敗則排入 cleanup，且永不發布 credential metadata。每個來源 work ID 會 pin 單一 credential version 及不可續租的絕對 lease window，checkout 必須攜帶 workload、environment、source／destination、purpose、request／work ID 及五分鐘 lease duration；同一 resolver 只回傳同一 lease，跨 resolver 的 checkout 也受原始 pin expiry 限制。Resolver 以單一 lock 原子化 cache prune、terminal readiness、pin、checkout 與 insert；兩個 thread 同時解析相同 work ID 只會取得同一 lease、形成一次 SecretProvider checkout，不會留下 losing plaintext lease。`SecretLease` 的 issued／expiry／purpose metadata 唯讀，由 provider-owned wall clock 建立並以 monotonic deadline 執行到期，且禁止序列化；caller 不能改時間或替同一 work 取得新的五分鐘視窗，rotation 後的同一 work 也不會切換到 mutable latest。含明文的 resolver lease cache 以 64 筆為上限；lease 的到期 scheduler 不需等待下一次 resolver 呼叫就會 revoke 並清空 credential map，容量淘汰亦會立即清空。Validation 在成功或失敗回傳前也會於 `finally` 清空暫存 credential map 並立即 revoke lease，不讓五分鐘 timer 成為明文保留期；已 pin 的 work 每次重用前仍會檢查 terminal credential readiness，revoke、validation failed 或 expiry 會先移除並清空快取 lease，只有合法 rotation pin 能繼續沿用原 credential version。credential 的當前撤銷／到期／secret 損壞狀態會即時投影到研究資格 REST／UI 的新擷取、特徵、訓練及研究展示，且不會接觸 provider。Authentication evidence 與 reason／contract／dataset codes 是封閉型別，readiness／reason／authentication／source assessment 的矛盾組合會在 provider boundary 被拒絕；另有獨立不可變 `source_contract_assessment` artifact 記錄 provider／dataset 健康。`401` 判定 authentication failed；初次 `403` 因同時可能代表錯誤 credential 或權限不足而維持 inconclusive，只有同一次 live probe 已先成功驗證 authentication 時，後續 `403` 才記為 source contract forbidden。validator exception／回顯 credential 及 collector 收到任何回顯 credential 的 provider payload 都會以不含 secret 的固定 reason fail closed；包括不可雜湊或惡意 domain reason 也只會逸出固定 allowlist reason，且切斷原始 exception chain。Operations 瀏覽器 session 亦有 TTL 清理與 256 筆上限。Credential REST 拒絕未知欄位，限制 8 個欄位、key 128 字元、value 4096 字元及總 body 16 KiB；OpenAPI 明列相同 bounds 與 `413` problem response。
- 永久 listing identity、symbol aliases、lifecycle 與必要公司行動由同一個版本化 reference graph 推導，graph version／完整度會綁定 raw bundle、retrieval receipt、quarantine 或 dataset lineage；caller 不得自行宣稱公司行動完整。Candidate graph 不補造未知 lifecycle，未有完整外部證據時 fail closed。
- 零付費方案的部署主體分類會在 source policy evaluation 實際比對並綁入不可變 current-rights decision identity／artifact，`individual_non_commercial` 等 principal classification 不只保存於 metadata；不相符時以 `source_policy_principal_classification_denied` 阻斷。
- 歷史分區依版本化 alias 有效區間選出所有重疊 ticker，以 provider 的 `asof=-` 保留當時 symbol；decoder 以 `(symbol, session_date)` 解析永久 listing identity，允許不同 listings 的不重疊 ticker reuse，拒絕重疊區間，並以 `identity_ambiguous` 隔離有效期外資料與重複 canonical price key。跨更名區間會同時擷取舊／新 symbol，並依每個交易日當時有效的 alias 計算 coverage，不以最後一個 ticker 代替歷史身分；name change 的舊／新 symbol 必須在事件前後各自解析到同一 listing，否則 action assertion 不計入 completeness 並同時形成 `identity_ambiguous`／`missing_company_action`。
- Provider `403`／`5xx`／transport 失敗會在 `DataSupply.materialize`、研究資格 REST 與 UI 發布穩定的 `unavailable`，不建立 raw object、dataset 或 adjustment；HTTP response 以 8 MiB 上限讀取，超限同樣 fail closed。公司行動分頁的重複 action ID 會形成 `duplicate_company_action` 並隔離，不能重複調整。交易日曆 completeness 會逐日比對版本化、不可由 caller 宣稱的預期 session evidence；provider 遺漏中間交易日或超出 evidence coverage 都不會發布 dataset，evidence version 同時綁入 raw bundle 與 retrieval receipt。
- Live provider egress 與 SecretProvider checkout 前必須先寫入不含 plaintext credential 的不可變 security audit；audit 寫入失敗時在接觸 provider／secret storage 前 fail closed。checkout 由單一 audited boundary 寫入每次獨立的 `attempted` 與真實 `succeeded`／`failed` 終態；任意 provider exception（包括帶有非 allowlist 訊息的 domain exception）都會在離開 boundary 前轉成固定 reason 並切斷原始 exception chain，known-value canary 不會進 response、exception、audit 或 trace。成功終態無法保存時不回傳 lease。Bundle policy evaluation 會按實際順序逐項保存先前的 allow，即使後續 member deny 也不遺失。checkout audit 只保存 provider、credential version、使用 context 與 opaque secret reference，source egress audit 保存 policy evaluation 與 distribution identity。
